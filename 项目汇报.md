## 🎯 核心工作内容

### 第一部分：单一系统拆分为三个子系统

#### 1.1 问题分析

**原有系统的问题：**
- 所有功能（管理员、教师、学生）混在一个界面中
- 只有一个统一的登录入口，登录后根据 `user_type` 跳转
- 权限控制分散在各个视图函数中，代码重复
- 用户体验差，不同角色看到的功能混杂

**改造目标：**
- 将系统拆分为三个独立的子系统（管理员、教师、学生）
- 为每个角色创建独立的登录入口
- 实现统一的权限控制机制
- 每个角色只能看到和访问自己的功能模块

```python
from django.contrib.auth.backends import ModelBackend
from django.contrib.auth import get_user_model

class EmailBackend(ModelBackend):
    """
    自定义认证后端：使用邮箱替代用户名进行登录
    """
    def authenticate(self, request, username=None, password=None, **kwargs):
        UserModel = get_user_model()
        try:
            # 使用邮箱查找用户
            user = UserModel.objects.get(email=username)
        except UserModel.DoesNotExist:
            return None
        else:
            # 验证密码
            if user.check_password(password):
                return user
        return None
```

**技术要点：**
- **自定义认证后端**：继承 `ModelBackend`，重写 `authenticate` 方法

##### 1.2.2 权限控制中间件（谢树荟负责）

**开发逻辑：**

**问题：** 原系统在每个视图函数中都要检查用户类型和权限，代码重复且容易出错。

**解决方案：** 使用Django中间件在请求处理前统一进行权限检查。

**实现步骤：**

**步骤1：创建权限控制中间件**

创建 `main_app/middleware.py`：

```python
from django.utils.deprecation import MiddlewareMixin
from django.urls import reverse
from django.shortcuts import redirect

class LoginCheckMiddleWare(MiddlewareMixin):
    """
    权限控制中间件：基于用户类型和视图模块名进行权限检查
    """
    def process_view(self, request, view_func, view_args, view_kwargs):
        modulename = view_func.__module__  # 获取视图函数所在的模块名
        user = request.user
        
        # 允许登录相关路径通过
        login_paths = [
            reverse('login_page'),
            reverse('user_login'),
            reverse('admin_login'),
            reverse('teacher_login'),
            reverse('student_login'),
            reverse('user_logout'),
        ]
        
        if request.path in login_paths or request.path.startswith('/do-'):
            return None  # 放行登录相关路径
        
        # 允许静态文件和媒体文件通过
        if request.path.startswith('/static/') or request.path.startswith('/media/'):
            return None
        
        # 已登录用户的权限检查
        if user.is_authenticated:
            if user.user_type == '1':  # 管理员
                # 管理员不能访问教师和学生的视图
                if modulename == 'main_app.student_views' or modulename == 'main_app.staff_views':
                    return redirect(reverse('admin_home'))
            elif user.user_type == '2':  # 教师
                # 教师不能访问管理员和学生的视图
                if modulename == 'main_app.student_views' or modulename == 'main_app.hod_views':
                    return redirect(reverse('staff_home'))
            elif user.user_type == '3':  # 学生
                # 学生不能访问管理员和教师的视图
                if modulename == 'main_app.hod_views' or modulename == 'main_app.staff_views':
                    return redirect(reverse('student_home'))
            else:
                # 未知用户类型，重定向到登录页
                return redirect(reverse('login_page'))
        else:
            # 未登录用户，重定向到登录页
            return redirect(reverse('login_page'))
```

**技术要点：**
- **中间件机制**：继承 `MiddlewareMixin`，实现 `process_view` 方法
- **模块名判断**：通过 `view_func.__module__` 获取视图所在模块，判断视图所属角色
- **统一权限控制**：在中间件层面统一处理，避免在每个视图函数中重复代码
- **路径白名单**：登录相关路径和静态文件路径直接放行

**步骤2：在settings.py中注册中间件**

```python
MIDDLEWARE = [
    'django.middleware.security.SecurityMiddleware',
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.common.CommonMiddleware',
    'django.middleware.csrf.CsrfViewMiddleware',
    'django.contrib.auth.middleware.AuthenticationMiddleware',
    'django.contrib.messages.middleware.MessageMiddleware',
    'django.middleware.clickjacking.XFrameOptionsMiddleware',
    
    # 自定义权限控制中间件
    'main_app.middleware.LoginCheckMiddleWare',
]
```

**技术要点：**
- **中间件顺序**：放在 `AuthenticationMiddleware` 之后，确保 `request.user` 已设置
- **全局生效**：所有请求都会经过此中间件进行权限检查

```python
from django.core.paginator import Paginator, EmptyPage, PageNotAnInteger
from django.db.models import Q

def paginate_queryset(request, queryset, per_page=10):
    """通用分页工具函数"""
    paginator = Paginator(queryset, per_page)
    page = request.GET.get('page', 1)
    try:
        page_obj = paginator.page(page)
    except PageNotAnInteger:
        page_obj = paginator.page(1)
    except EmptyPage:
        page_obj = paginator.page(paginator.num_pages)
    return page_obj, paginator

def search_students(queryset, search_query):
    """学生搜索功能"""
    if search_query:
        queryset = queryset.filter(
            Q(first_name__icontains=search_query) |
            Q(last_name__icontains=search_query) |
            Q(email__icontains=search_query)
        )
    return queryset
```

**技术要点：**
- **代码复用**：将分页、搜索等通用功能抽象为工具函数

#### 2.2 数据模型设计（易经负责）

**开发逻辑：**

**步骤1：设计活动核心模型**

在 `main_app/models.py` 中添加活动相关模型：

```python
class Activity(models.Model):
    """
    校园活动模型
    """
    STATUS_CHOICES = [
        (0, '待审批'),
        (1, '已通过'),
        (2, '已拒绝'),
    ]
    
    title = models.CharField(max_length=200, verbose_name='活动标题')
    description = models.TextField(verbose_name='活动描述')
    organizer = models.ForeignKey(Staff, on_delete=models.CASCADE, verbose_name='发起教师')
    location = models.CharField(max_length=200, verbose_name='活动地点')
    start_time = models.DateTimeField(verbose_name='开始时间')
    end_time = models.DateTimeField(verbose_name='结束时间')
    max_participants = models.IntegerField(
        default=0, 
        verbose_name='最大参与人数',
        help_text='0表示不限制'
    )
    status = models.SmallIntegerField(
        default=0, 
        choices=STATUS_CHOICES, 
        verbose_name='审批状态'
    )
    admin_reply = models.TextField(blank=True, null=True, verbose_name='管理员回复')
    created_at = models.DateTimeField(auto_now_add=True, verbose_name='创建时间')
    updated_at = models.DateTimeField(auto_now=True, verbose_name='更新时间')
    
    class Meta:
        verbose_name = '校园活动'
        verbose_name_plural = '校园活动'
        ordering = ['-created_at']  # 按创建时间倒序
    
    def __str__(self):
        return self.title
```

**技术要点：**
- **状态管理**：使用 `STATUS_CHOICES` 定义活动状态（待审批/已通过/已拒绝）
- **外键关联**：`organizer` 关联到 `Staff` 模型，表示活动发起教师
- **级联删除**：使用 `on_delete=models.CASCADE`，删除教师时自动删除其创建的活动
- **时间字段**：使用 `DateTimeField` 存储活动的开始和结束时间
- **元数据配置**：使用 `Meta` 类配置模型的显示名称和排序方式

```python
def student_register_activity(request, activity_id):
    """
    学生报名活动（AJAX异步）
    """
    if request.method == 'POST':
        activity = get_object_or_404(Activity, id=activity_id, status=1)  # 只能报名已通过的活动
        student = get_object_or_404(Student, admin=request.user)
        
        # 检查是否已报名
        if ActivityRegistration.objects.filter(activity=activity, student=student).exists():
            return JsonResponse({'success': False, 'message': '您已经报名过此活动'})
        
        # 检查报名人数限制
        if activity.max_participants > 0:
            current_count = ActivityRegistration.objects.filter(activity=activity).count()
            if current_count >= activity.max_participants:
                return JsonResponse({'success': False, 'message': '活动报名人数已满'})
        
        # 创建报名记录
        ActivityRegistration.objects.create(activity=activity, student=student)
        return JsonResponse({'success': True, 'message': '报名成功'})
    
    return JsonResponse({'success': False, 'message': '请求方法错误'})

    """
    学生查看已报名的活动
    """
    student = get_object_or_404(Student, admin=request.user)
    registrations = ActivityRegistration.objects.filter(
        student=student
    ).select_related('activity', 'activity__organizer', 'activity__organizer__admin')
    
    context = {
        'registrations': registrations,
        'page_title': '我的活动'
    }
    return render(request, 'student_template/my_activities.html', context)

def student_feedback_activity(request, activity_id):

    学生评价活动
    """

        messages.error(request, "您未报名此活动，无法评价")
        return redirect(reverse('student_view_activities'))
    
    # 检查是否已评价

    context = {
        'activity': activity,
        'form': form,
        'feedback_exists': feedback_exists,
        'page_title': '活动评价'
    }
    return render(request, 'student_template/feedback_activity.html', context)
```

#### 2.7 活动管理模块的技术总结

**核心技术点：**

1. **数据模型设计**
   - 使用外键关联实现多表关系
   - 使用 `unique_together` 确保数据完整性
   - 使用状态字段实现业务流程控制

2. **查询性能优化**
   - 使用 `select_related` 优化外键查询
   - 使用 `prefetch_related` 优化反向关联查询
   - 避免N+1查询问题

3. **AJAX异步操作**
   - 使用jQuery实现异步报名
   - 使用 `JsonResponse` 返回JSON数据
   - 提升用户体验

4. **业务逻辑验证**
   - 检查重复报名、重复评价
   - 检查报名人数限制
   - 检查活动状态（只能报名已通过的活动）

5. **状态流转机制**
   - 活动状态：待审批(0) → 已通过(1) / 已拒绝(2)
   - 通过状态字段控制业务流程
